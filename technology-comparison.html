What the completed results show

  • The vanilla comparison favors Vaadin in both harnesses. The observed gap is 55 percentage points with Codex and 25 points with Claude Code.
  • Tooling effects differ. Codex scores 16/20 vanilla, 13/20 with MCP only and 19/20 with skills + MCP. Claude scores 17/20, 18/20 and 16/20 respectively. MCP only does not improve both harnesses in this sample.
  • A combined tooling advantage is not consistent across harnesses. Skills + MCP adds three passes over vanilla for Codex but loses one for Claude. These are small samples; they do not establish a general causal effect.
  • Keep model-level comparisons visible. Model prices, effort levels and successful-run subsets differ. Use the per-model tables rather than pooled successful-run cost or timing averages.

Comparability and limits

Both tasks use the same one-line instruction and identical UC-002 use-case text and shared business rules in the inspected submissions. Both allow 2 CPUs, 4 GB RAM, a 60-minute agent phase and a 20-minute verifier phase. Fixture code, the 1,000-vet dataset, a 200-result-row loading-step budget and 20-second browser interaction timeouts are matched.

The complete stacks differ: Angular + Quarkus + JPA versus Vaadin Flow + Spring Boot + jOOQ. Angular needs frontend/backend integration and its own paging UI; Vaadin supplies a Grid component and backend data-provider integration. Angular checks browser-visible behavior; Vaadin combines server-side component tests with browser tests and requires a Vaadin Grid. Their scroll-driving mechanisms differ. Those differences are part of this benchmark.

There is one task pair and five repetitions per model/effort/configuration. A single trial changes a model cell by 20 percentage points. Results are descriptive scores under these verifiers, not a general ranking of frontend technologies or application runtime performance. MCP-only trials ran later in a separate suite; order and provider state are not randomized.

One original Claude attempt ended with a revoked OAuth token and was replaced after authentication recovered. The 160 scored results use the valid replacement and exclude the interrupted attempt’s time and cost. This report covers scored trial estimates, not all money or quota consumed while operating the suites. No benchmark tests or submitted solutions were modified for this report.

* Astra, Angular: All five trials sorted vets by database ID (order by v.id) rather than the surname/first-name order enforced by both verifiers. They failed the ordering assertion and timed out waiting for Lazy0001 on the initial page. That timeout alone does not demonstrate a scrolling defect. Builds, navigation, empty-list handling and welcome-page tests passed. The linked UC-002 specification explicitly orders specialties alphabetically but does not explicitly require surname/first-name veterinarian ordering. Therefore these are failures against an additional verifier expectation, not established violations of that written requirement. The recorded scores have been retained.
